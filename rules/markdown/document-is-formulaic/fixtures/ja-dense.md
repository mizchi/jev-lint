# 画像変換 API を Lambda から Fargate に戻した話

社内の画像変換 API（アップロードされた画像を 3 サイズにリサイズして S3 に置く）を、2 年前に Fargate から Lambda に移し、先月 Fargate に戻した。移した理由と戻した理由は両方とも数字で、この記事はその数字を残しておくためのもの。

## 前提

- リクエスト数: 平日日中 40〜60 req/s、夜間 2〜5 req/s。月間 8,000 万リクエスト前後
- 入力: JPEG/PNG、中央値 1.8 MB、p99 で 11 MB
- 処理: libvips でデコード → 3 サイズにリサイズ → WebP エンコード → S3 に 3 オブジェクト PUT
- 処理時間: 中央値 210 ms、p99 で 1.9 s（p99 は 11 MB の PNG がほぼ全部）

## Lambda に移した理由（2 年前）

当時は Fargate で 2 vCPU / 4 GB のタスクを最低 4、最大 20 でオートスケールしていた。夜間の 2 req/s に対して 4 タスクは明らかに余っていて、月額はおよそ 620 ドル。Lambda（2,048 MB、arm64）に移したら月額 180 ドルまで落ちた。当時の判断は正しかったと今でも思っている。

## 戻すことになった経緯

昨年秋から日中のピークが 60 req/s から 140 req/s まで伸びた。原因は別チームがサムネイル生成をこの API に寄せてきたことで、こちらは把握していなかった。Lambda の請求は 3 か月で 180 ドル → 470 ドル → 890 ドルと伸びた。

計算すると、Lambda の 1 リクエストあたりの単価は 210 ms × 2,048 MB でおよそ 0.0000070 ドル。月 2 億リクエストに近づくと 1,400 ドルを超える。Fargate なら 2 vCPU / 4 GB のタスク 1 つで安定して 25 req/s さばけることが負荷試験でわかっていたので、ピーク 140 req/s に対して 6 タスク、夜間 1 タスクにすれば月額 400 ドル前後で収まる。

もう一つ、Lambda では p99 が 1.9 s から 3.4 s に悪化していた。コールドスタートではなく、libvips が 2,048 MB の制約の中で 11 MB PNG をデコードするときにスワップ気味になっていたのが原因（`vips_concurrency` を 1 に落としても変わらなかった）。メモリを 3,008 MB に上げると p99 は 2.1 s に戻ったが、単価は 1.5 倍になる。

## 移行でやったこと

1. Fargate 用の Dockerfile を復活させた。2 年前のものは libvips 8.12 だったので 8.15 に上げ、`sharp` の prebuilt を使わず libvips を直接リンクするようにした。イメージサイズは 410 MB → 190 MB
2. オートスケールの指標を CPU 使用率から ALB の `RequestCountPerTarget` に変えた。CPU 使用率だとスケールアウトの判断が 3 分遅れて、ピーク立ち上がり時に p99 が 5 s を超えた
3. 最低タスク数を 1 にした。夜間 5 req/s なら 1 タスクで足りる
4. Lambda 版は 2 週間並行稼働させ、ALB の重み付けで 10% → 50% → 100% と Fargate に寄せた

## 結果（移行後 4 週間）

| | Lambda（移行前） | Fargate（移行後） |
| --- | --- | --- |
| 月額 | 890 ドル | 430 ドル |
| p50 | 210 ms | 190 ms |
| p99 | 3.4 s | 1.7 s |
| 5xx 率 | 0.02% | 0.01% |

p50 が 20 ms 縮んだのは、Fargate 側で libvips のスレッドを 2 に固定して並列デコードが効くようになったため。

## 反省

- 別チームの利用増を請求額で気づいたのは遅い。API Gateway のクライアント別の使用量プランを設定しておけば、増えた時点でアラートが出せた。今回それを入れた
- 「Lambda は安い」は 50 req/s 以下の話で、常時 100 req/s を超える CPU バウンドな処理は Fargate の方が安いというのを、2 年前に損益分岐点として書き残しておくべきだった。今回は書いた: この API の場合、平均 90 req/s を超えたら Fargate
- 戻すのに 3 週間かかった。半分は Dockerfile の復活で、2 年前のものが残っていなければもっとかかっていた。廃止した構成のファイルは消さずに `deprecated/` に残す、という運用にした
