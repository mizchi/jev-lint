# 停止時間は何に比例するか

ヒープを倍にしたら GC の停止時間が倍になった、という報告を受けた。倍になるはずがない。生き残るオブジェクトの量が変わっていないなら、停止時間も変わらないはずである。

## 生き残る量

なぜ死んだオブジェクトの量が停止時間に効かないのか。コピー型の GC は、生きているオブジェクトを辿って新しい領域に写し、辿らなかったものをまとめて捨てるからである。捨てる側には一切触らない。触るのは生きている側だけで、その量が停止時間を決める。

ヒープを倍にすれば、GC の回数は半分になる。一回あたりの停止時間は、生き残る量が同じなら同じである。合計の停止時間は半分になる。報告と逆である。

報告が間違っているに違いない。

## 報告のほう

「うちのサービスでは倍になっている」と言われれば、測り方を疑うのが筋だろう。測り方は正しかった。倍になっていたのは、生き残る量のほうだった。

ヒープを倍にした結果、GC の回数が減り、一回の GC までに溜まるリクエストの処理途中のオブジェクトが倍になっていた。処理途中のオブジェクトは生きている。生きている量が倍になれば、停止時間は倍になる。生き残る量は一定だ、という前提のほうが崩れていたのであって、比例の法則は崩れていなかった。

## 落としどころ

要するに、停止時間は生き残るオブジェクトの量に比例し、死んだ量には比例しない。この一文は正しいまま、ヒープを倍にすると生き残る量が変わる、という但し書きが付いた。

停止時間を短くしたいなら、生き残る量を減らす。処理途中のオブジェクトを減らすには、一回のリクエストで持つ中間データを減らすか、GC を頻繁に走らせて処理途中の重なりを減らすか。後者はヒープを小さくすることで、冒頭の報告とちょうど逆の操作になる。ヒープを小さくして停止時間が短くなるサービスは、たしかに存在する。
