# Webhook の即時リトライをやめた理由

多くの Webhook システムは、配信に失敗するとすぐにリトライする。失敗は一時的なものだろう、という前提に立っているからだ。自分たちも以前はそうしていたが、これは解決する以上に問題を生んでいた。

問題は、失敗が一時的なものではなく構造的なものだったときに、即時リトライが何をするかにある。受信側のエンドポイントが落ちている、あるいは自分たちからのリクエストをレート制限している場合、即時リトライは同じ壊れたエンドポイントにもう一度当たり、同じ失敗を得て、またすぐにリトライする。しかもそれは、最初の失敗を引き起こしたのとまったく同じ状態が続いている間に起きる。受信サーバーが過負荷で落ちているのだとしたら、失敗した送信側全員が一斉に即時リトライすることは、助けになるどころか逆効果で、最悪のタイミングで追加の負荷をかけているだけだ。

そこで、ジッターを加えた指数バックオフに切り替えた。失敗した配信は最初のリトライまで待ち、2回目のリトライまではさらに長く待ち、その待ち時間は固定ではなく一定の幅の中でランダム化する。同じ瞬間に一斉に失敗した Webhook 群が、次も一斉に同じ瞬間にリトライしないようにするためだ。ジッターが重要なのはまさにこの点で、これがないと全クライアントが足並みを揃えてバックオフし、次のリトライも同じタイミングで一斉に当たることになり、1 サイクル後に同じ過負荷問題を再現してしまう。

また、無限にリトライすることもやめた。一定回数を超えて失敗し続ける Webhook はデッドレターキューに送り、それ以上リトライしない。長期間壊れたままの受信エンドポイントは、もう一度自動でリトライすべき対象ではなく、人間が見るべき対象だからだ。
